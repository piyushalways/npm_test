# nPM1300 + EMS Stimulation — Dual-Thread Firmware

Bring-up / bench firmware for a custom PCB built around an **nRF54L15** MCU and an
**nPM1300** PMIC, targeting the **nrf54l15dk_nrf54l15_cpuapp** board.

It runs two things **concurrently**:

1. **EMS stimulation** — the electrical-muscle-stimulation waveform, generated by the
   nRF54L15's own PWM + GRTC peripherals (engine in [`src/ems_hw/`](src/ems_hw/)).
2. **nPM1300 LED + GPIO heartbeat** — a visible activity indicator driven over I²C.

The two run on **separate Zephyr threads** and use **disjoint hardware**, so the stim
waveform and the PMIC heartbeat never interfere.

---

## Quick start

```bash
west build -b nrf54l15dk_nrf54l15_cpuapp -p
west flash
```

Console/logs/shell are routed over **SEGGER RTT** (no UART). Open **J-Link RTT Viewer**
(or `JLinkRTTLogger`) to see output.

## Architecture

```
BOOT → main():
  ├─ start ems_wq (engine's discharge work queue)
  ├─ probe devices (NON-FATAL): PMIC, LEDs, GPIO, LS1 rail
  ├─ ems_init()                         ← only hard requirement for stim
  ├─ enable LS1 once (if present)        ← HV stim rail, never toggled again
  ├─ apply EMS params (mode→intensity→pulse→duration)
  ├─ create stim thread        (ALWAYS)
  └─ create led_gpio thread    (only if PMIC detected)

Thread: stim                      Thread: led_gpio
  ems_start()                       loop:
  poll until IDLE                     LEDs + GPIO1/2/3 ON  (I²C)
  (heartbeat log every 10 s)          sleep 500 ms
  ems_stop()                          LEDs + GPIO1/2/3 OFF (I²C)
  (one-shot or loop)                  sleep 500 ms
```

### The EMS engine (treated as a black box)

The engine in [`src/ems_hw/ems_engine.c`](src/ems_hw/ems_engine.c) was ported verbatim
from the DUSQ project. It generates the waveform entirely from **hardware interrupts**
(nrfx PWM20/21/22 + GRTC compare ISRs) — once started, no thread CPU time is needed to
sustain it. `main.c` only *drives* it; the engine files are not modified.

Timing is a 3-level nested structure:

```
carrier pulses  →  bursts (5 ms on / 5 ms gap)  →  stim window (1.5 s)  →  rest (0.5 s)  →  repeat
```

### Power rails

- **LS1** (`npm1300_ek_ldo1`) is the EMS high-voltage stim rail. It is enabled **once** at
  startup and **left on** — no toggling.
- **LS2 / VOUT1 / bucks** are left at their overlay/boot defaults and are never touched.

## Signal map (oscilloscope)

| MCU pin | Source | Net | Style | What you see (RELAX, intensity 40) |
|---|---|---|---|---|
| **P1.13** | PWM20 | carrier | PWM | ~64 µs period (~15.6 kHz), bursty: 5 ms on / 5 ms gap |
| **P1.11** | PWM21 | stim E1 | PWM | ~1 kHz, ~90 % duty, packets of ~3 pulses, alternates with E2 |
| **P1.07** | PWM22 | stim E2 | PWM | same as E1, on the opposite bursts |
| **P0.0**  | GPIO  | CAP / discharge | on/off | HIGH 60 s after boot; HIGH during rest, LOW during stim window |
| **nPM1300 GPIO1/2/3** | I²C | heartbeat | on/off | 500 ms blink (parallel with stim) |
| **nPM1300 RGB LEDs**  | I²C | heartbeat | on/off | 500 ms blink |

> The stim signals are **gated and short** — a free-running scope or a multimeter looks
> dead. Probe **P1.13** at ~1 ms/div, edge-triggered, to confirm the carrier bursts.

## Configuration

All tunables are in a single `#define` block at the top of
[`src/main.c`](src/main.c) — edit and rebuild:

```c
/* EMS stimulation */
#define EMS_MODE              EMS_MODE_RELAX   /* SLEEP / RELAX / BREATH / CUSTOM */
#define EMS_INTENSITY         40               /* 1..100 */
#define EMS_PULSE_WIDTH_PCT   90               /* 1..100 */
#define EMS_SESSION_SECONDS   1200             /* bounded run; 0 = infinite */
#define EMS_CONTINUOUS        0                /* 0 = one session then idle, 1 = loop forever */
#define EMS_INTERSESSION_MS   2000             /* gap between sessions when CONTINUOUS=1 */
#define EMS_PROGRESS_LOG_S    10               /* "still running" log cadence (s) */

/* LED / GPIO heartbeat */
#define LED_BLINK_PERIOD_MS   500
```

### Common run modes

| Goal | Settings |
|---|---|
| One 20-min session, then idle | `EMS_SESSION_SECONDS 1200`, `EMS_CONTINUOUS 0` (default) |
| Run forever, single non-stop session | `EMS_SESSION_SECONDS 0` |
| Loop sessions forever (gap between each) | `EMS_CONTINUOUS 1` |

## Expected RTT log

```
========================================
  NPM1300 + EMS Dual-Thread Application
========================================
Devices — PMIC:ok  LEDs:ok  GPIO:ok  LS1:ok
[EMS] === Init start ===
[EMS] GRTC event init OK (CC_A=ch.., CC_B=ch..)
[EMS] === Init complete ===
✓ EMS stim rail (LS1) enabled (stays on)
✓ stim thread launched (prio 7)
✓ led_gpio thread launched (prio 8)
[led] heartbeat started (500 ms)
[stim] session started (mode=1, intensity=40, 1200 s)
[EMS] FSM → BURST_GAP (enabled, mode=3, intensity=40)
[stim] running... state=1, elapsed=10 s
[led] heartbeat alive (10 cycles)
[stim] running... state=3, elapsed=20 s
        ... interleaved for the full session ...
[EMS] Session complete (600 cycles)
[EMS] FSM → IDLE (disabled)
[stim] session complete
```

The interleaved `[stim]` and `[led]` lines are the proof that both threads run in
parallel. The changing `state=` value (1/2/3) shows the engine actively cycling through
burst / gap / rest.

## Behavior notes & safety

- **PMIC is non-fatal.** If the nPM1300 is not detected, stimulation **still runs** (you
  can scope the PWM) — only the LED/GPIO heartbeat and the HV rail are skipped. This also
  serves as an isolation test: PWM with no PMIC ⇒ the MCU signal path is good.
- **HV discharge.** Because LS1 stays energized, the firmware deliberately does **not**
  call `ems_discharge_after_stop()` between sessions — bleeding the inductor against a
  live rail is unsafe. `ems_stop()` alone returns the engine to a safe IDLE state. A true
  inductor discharge happens only on reset/power-off (and the 60 s boot-grace bleed).
- **Parameter order matters.** `ems_set_session_duration()` is called **last**, after
  `ems_set_mode()`, because the session's cycle limit is derived from the mode's
  stim+rest timing.
